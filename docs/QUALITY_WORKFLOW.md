# Качество оценщика и рабочее место проверяющего — 8 ноября 2026

Изменение объединяет новую версию инструкций Xerosharc и работу с результатами:
баллы и нарушения в списке, серверный поиск и сортировку, очереди проверки,
редактирование одного критерия и сравнение двух оценок одного текста.
API 1.4.0 сохраняет прежние маршруты и совместимость старых DTO.

## Что именно изменилось в оценщике

`live-xerosharc-quality-v1` версии `1` закрепляет `cqa-eval-v4` и запрашивает
`gpt-6.1-sol` у Xerosharc. Шлюз сообщает `xeros_core`; идентичность модели за
шлюзом не подтверждена. Сначала оценщик проверяет N/A, затем логические условия
и порядок действий, доказательства и согласованность объяснения с ответом.
Правила исходного чек-листа и domain scoring не менялись.

Первый пилот v3: 6 DEV-разговоров, 10 из 12 выбранных проверок совпали с разбором
правил. Не были распознаны два раскрытия состояния счёта без идентификации.
В v4 уточнено различие общей инструкции и сведений о конкретном счёте, а также
согласованность фактов между критериями. Два повторно разобранных случая дали
4 из 4 ожидаемых ответов. Один дополнительный выдуманный пример с системным
подтверждением личности до раскрытия дал 2 из 2 ожидаемых ответов.

Это малый диагностический набор, **не закрытая разметка организаторов и не оценка
общей точности**. Первые примеры участвовали в настройке. Дополнительный пример
не включён в официальный DEV и проверяет только одну обратную ситуацию.
Reviewer выключен; политика `keep_valid_initial_v1` не менялась и не выдаётся
за способ автоматически разрешать допустимые разногласия.

## Как воспроизвести сравнение

Настоящий прогон использует тот же приватный manifest из 65 DEV-разговоров и
ту же закреплённую исходную рубрику. Для нового профиля создаются fresh jobs,
не reuse. В receipt сохранён отдельный batch каждого разговора; два результата
пилота v4 используются повторно как уже выполненные задания того же receipt.
Одновременно работают не более двух заданий. Повторы формата и транспорта
ограничены профилем; сырые ответы, БД и тексты в Git не публикуются.

Сравниваются сохранённый финальный Gemini/v2 и новый Xerosharc/v4. Меняются
и провайдер, и инструкции; это **не эксперимент, изолирующий качество модели**.
Исторический финальный Gemini сформирован с дополнительными запусками, поэтому
его 65 полных ответов нельзя выдавать за результат одного безошибочного прохода.

## Рабочее место

- Поиск по ID и тексту RU/KZ/EN, порог балла и сортировка выполняются до пагинации.
  Неизвестный итог не превращается в ноль. Старый балл не показывается вместо
  нового pending/failed задания.
- Быстрые очереди выделяют обнаруженные флаги, неполные/спорные оценки,
  ошибки и открытые апелляции выбранной последней оценки. Общая очередь сохраняет
  апелляции по всей истории. Источник AI/пересмотр явно выбран.
- Редактор показывает один критерий и навигацию по остальным; технические значения
  и доли раскрываются отдельно. Изменение шкалы требует прежнего подтверждения,
  история и защита черновика сохранены.
- Сравнение показывает серверные итоги, ответы, основания и изменения рубрики.
  Разные версии текста не сравниваются как повторная оценка одного разговора.
  Ссылки на доказательства сохраняют выбранный источник результата.
- Предпочтительный профиль задаётся `CQA_DEFAULT_EVALUATOR_PROFILE`.
  Не настроенный предпочтительный профиль не подменяется другим при запуске.
  Вызовы показывают input/output из API; reasoning не считается второй раз.

## Проверка и ограничения публикации

Новый браузерный сценарий использует настоящий API с явным синтетическим
оценщиком: поиск, очередь, переход к апелляции, новая версия весов, переиспользование
ответа без AI-вызова, сравнение 25 → 75, доказательства и запрет сравнения другого
текста. Снимки 1440×900 и 390×844 просмотрены; README использует только выдуманные
разговоры с видимой отметкой тестового режима.

Локально запускались проверки затронутых компонентов; полный набор оставлен CI.
Автотесты подтверждают работу приложения, а не семантическую точность модели.
Стоимость в USD неизвестна: подтверждённых правил списания купленного у посредника
пакета нет. Полнота расхода токенов и полнота цены — разные свойства.

Предоставленный финальный DEV не заменяется автоматически. Новый экспорт
проверяется по сохранённым данным и остаётся приватным кандидатом. Неполные ответы
не дополняются выдуманными значениями ради успешного экспорта. CONTROL/PROD
не получен; результаты DEV и один выдуманный пример его не заменяют.
