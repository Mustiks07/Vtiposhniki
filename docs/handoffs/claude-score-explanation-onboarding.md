## A. «Почему снижена оценка» (настоящая карточка)

`src/lib/scoreExplanation.ts` (`explainScore`) + `src/components/ScoreExplanation.tsx`,
подключены в `EvaluationPage` сразу после итога (до сводки запуска и списка критериев).

- Пункт снижения = критерий с положительным весом, `applicability=applicable` и серверной
  `score_fraction ≠ 1` из `contributions` выбранного scope. Метки «Да/Нет», `raw_value` и ID
  критериев не используются → обратные/пользовательские шкалы и произвольные ID работают.
  Нулевой вес не объявляется причиной. Порядок — порядок чек-листа (серверной величины потери нет).
- Пункт: номер и название, ответ/ступень, сохранённое обоснование (3 строки, раскрытие «полностью»),
  «Получено веса: X из Y» (`earned_weight`/`original_weight`) и отдельно «Вклад в итог (сервер)»
  (`normalized_contribution`, `≈` с точным значением в подсказке; null → «не рассчитан»).
  «+N баллов после исправления» не обещается.
- Действия: «Показать доказательство» (первый элемент; остальные — «ещё: m0005…») через
  существующий параметр `evidence=N` (тот же критерий, scope, revision, подсветка, фокус,
  на телефоне — вкладка разговора); «Полный разбор» = `selectCriterion`; «Оспорить» открывает
  существующую модальную форму апелляции этого критерия; при открытой апелляции — пометка.
- Первые три причины, остальные — «Показать все причины (N)».
- Состояния: N/A — блок «Не применялось (N/A)», «исключены из применимого веса — это не штраф»;
  undetermined/нет ответа/неизвестный флаг — «Требуется проверка», не штраф; partial —
  заголовок «Что известно об оценке» и «общий итог ещё не рассчитан», снижения по известным
  ответам показаны; все применимые выполнены — «По применимым критериям баллы не снижены» +
  указание, что нарушения проверяются отдельным флагом; нет применимого веса — «не 0 и не 100»;
  critical — отдельный красный блок «флаг не меняет и не обнуляет итог» с основанием и
  доказательством; «нарушение не обнаружено» и «не определено» разведены; чек-лист не загружен —
  загрузка/ошибка с повтором, без названий и чисел.
- automatic → `artifact.automatic_final` + `automatic_score`; effective → `effective_proposals` +
  `effective_score`. Переключатель ScorePanel меняет всё сразу. Ответ из решения проверяющего
  помечен «решение проверяющего», подпись источника называет scope и наличие решений; automatic
  остаётся доступен.

## B. Учебный пример

- «Посмотреть пример» — в действиях «Диалогов» и в пустом состоянии списка. Ничего не открывается
  автоматически. Маршрут `#/example/closing-na`, шаг хранится в `?step=`, refresh и «← Назад»
  работают (Назад → история, иначе «Диалоги»).
- Постоянная подпись: «Учебный пример. Ответы заданы для объяснения интерфейса; AI-запуск не
  выполнялся». Модель, токены, время, стоимость и история проверяющего не показываются.
- Использует те же `ScoreExplanation`, `explainScore`, `Transcript`, `TotalValue`, `ScaleTable`,
  что и настоящая карточка.
- Шаги: 1) почему не 100 — «Завершение», «Нет», 0 из 5; 2) «Подсветить завершающий участок» —
  m0003–m0004 и объяснение, что прощание клиента не заменяет действие оператора; 3) N/A для
  выявления потребности и идентификации, «не штраф», итог от 65; 4) «Вставить свой диалог»
  открывает существующую текстовую вставку (`#/conversations?paste=open[&example=closing-na]`,
  параметры сразу удаляются; текст в URL не передаётся). Перенос текста примера — только по
  флажку и только в пустое поле; иначе «в поле уже есть ваш текст — пример не перенесён».
  Импорт и запуск — отдельные действия пользователя; предупреждено, что настоящий профиль может
  ответить иначе.
- Страница не делает записей в API: не импортирует, не оценивает, не создаёт апелляций; данные
  встроены в сборку (отдельный lazy-чанк), в списки, статистику и экспорт не попадают.

### Происхождение учебных данных

`apps/web/scripts/build_tutorial_example.py` задаёт вымышленный диалог (4 реплики, вымышленный
сервис) и ответы вручную: контакт Да, потребность N/A, идентификация N/A, консультация p20,
эмпатия Да, ведение p10, завершение Нет, грубые ошибки Нет. Чек-лист —
`cqa_domain.sectioned_original_checklist()`, итог/вклады/флаги — `cqa_domain.score`. Скрипт
проверяет complete, 92.31, применимый вес 65, полученный 60 и пишет
`apps/web/src/tutorial/closing-na.json`. Это иллюстрация правил, не эталон и не результат AI;
`origin` предложений — `test`.

```sh
uv run python apps/web/scripts/build_tutorial_example.py          # пересоздать
uv run python apps/web/scripts/build_tutorial_example.py --check  # файл актуален
```

## Ограничения и пересечения

- Серверной «величины потери» нет, порядок причин — по чек-листу. Возможный запрос к API:
  `ScoreContribution.lost_normalized` (сколько баллов из 100 недополучено), чтобы сортировать
  по значимости без арифметики в UI.
- Тексты шагов примера написаны под конкретный пример `closing-na`; новые примеры потребуют
  своих текстов.
- `ImportPanel` получил необязательный проп; `ConversationsPage` — кнопку и обработку
  `paste=open`. При слиянии с параллельным редизайном экранов возможны текстовые конфликты в
  `page-actions` и пустом состоянии списка, а в `EvaluationPage` — рядом с `ScorePanel`/`RunDetails`.
- Синтетический оценщик выбирает первый вариант, поэтому E2E использует обратную шкалу и решение
  проверяющего; точность AI эти проверки не измеряют.
