## 1. Вставка диалога обычным текстом

Кнопка «Вставить диалог» на экране «Диалоги» открывает существующее окно импорта в режиме
«Вставить диалог обычным текстом»; JSON и API организаторов сохранены (кнопка «Импорт
разговоров» открывает их как раньше, по умолчанию JSON). Обе формы остаются смонтированными,
переключение источника не теряет ввод.

- Поля: язык RU/KZ/EN, канал «Чат» / «Расшифровка звонка», внешний ID (создаётся один раз как
  `paste-ГГГГММДД-ЧЧММСС-xxxxxx`, редактируется, «Новый ID»), текст, правила формата и пример.
- Формат (`src/lib/plainDialog.ts`): реплика — строка без отступа `[время] роль: текст`;
  время необязательно; роли `client/operator/bot/system` и документированные `клиент/оператор/
  бот/система` в любом регистре; строка с отступом (пробел/Tab) продолжает реплику с переводом
  строки (отступ-маркер не входит в текст), пустые строки внутри сохраняются, если за ними идёт
  продолжение; двоеточия и Unicode сохраняются; CRLF → LF.
- Время — только формы, которые понимает серверный импорт: `М:СС`/`ММ:СС`/`Ч:ММ:СС` и ISO 8601
  с часовым поясом. ISO без пояса, несуществующие даты, `[00:75]`, `[]` — ошибка с номером строки.
  Без времени реплика уходит с пустым `timestamp_original` (как в адаптере организаторов),
  не `00:00`; сервер при этом добавляет штатное предупреждение «source time not parsed».
- Неизвестная роль, строка без роли, продолжение без начала, пустая реплика, пустой ввод —
  понятные ошибки со строкой; импорт заблокирован, текст не теряется. Ничего не угадывается.
- Живой предпросмотр: №, роль, исходное время или «время не указано», текст, число сообщений.
  Предпросмотр и проверка вычисляются из текущего текста при каждом рендере.
- Отправка — существующий `JSONImport` через `POST /imports`, никакой клиентской БД.
  Синхронная защита от двойного клика; ID не меняется при повторе/ошибке («Повторить с тем же
  ID»). Повтор того же текста → `unchanged` («новый не создан»), изменённый текст с тем же ID →
  предупреждение до отправки и `new_revision` после. Это штатные правила сервера.
- После импорта: итог (создан / новая revision / без изменений), ссылка «Открыть разговор» и
  встроенная форма запуска оценки (тот же `BatchLaunchForm`, ключ идемпотентности и профили);
  фокус и прокрутка переходят к результату.

## 2. Сравнение оценок (существующая ComparisonPage)

`src/lib/comparison.ts` строит строки по объединению критериев обеих версий и использует
существующий `diffVersions`. Все числа — из `ScoreSummary`/`contributions` каждой стороны
(automatic → `automatic_final`+`automatic_score`, effective → `effective_proposals`+
`effective_score`). Формула итога в JS не реализована; decimal-строки сравниваются точно.

- Категории (пересекаются): критерий добавлен/удалён; изменено правило (название,
  определение, тип, инструкции канала, политика доказательств, источник, ответы-нарушения);
  условия N/A; шкала (варианты/доли); вес; секция; ответ; «тот же ID варианта, но другой смысл
  или доля»; применимость (N/A ≠ undetermined); ответ только с одной стороны; флаг; вклад в итог.
- Под строкой с изменённым правилом — «было → стало» для определения, N/A, вариантов с прежним
  ID и веса.
- Сводка: правила и веса / ответы, применимость и флаги / вклад в итог, с пояснением, что группы
  пересекаются и вклад меняется при изменении общего знаменателя.
- «Только изменения» (`changes=1` в URL) учитывает все категории, а не только `answer_choice_id`.
- Стороны: итог или «нет итога» с причиной, версия чек-листа, профиль, происхождение (новый
  вызов / ответы переиспользованы из оценки X), время, флаги, решения человека. Разница итогов —
  точное вычитание двух серверных итогов только когда оба `complete`; иначе явно не показывается.
  Изменение флага выводится отдельным блоком, даже если итог не изменился.
- Предупреждения: тестовый оценщик; разные профили («не только чек-лист»); разный текст/revision
  (сравнение запрещено, как раньше).
- «⇄ Поменять стороны», выбор сторон/scope/фильтра в URL, восстановление после refresh.
- Доказательства каждой стороны: «Реплики m0001–m0003» с цитатой → карточка нужной оценки,
  критерия и scope с `evidence=N`; карточка подсвечивает реплики этого доказательства (новый
  параметр в `EvaluationPage`, используется один раз и удаляется из URL). «Открыть доказательства»
  сохранён.
- Исправлен найденный дефект: после нового запуска кешированный список оценок не содержал
  запрошенный ID, и страница молча подставляла другую оценку. Теперь список перечитывается;
  если ID так и не найден — явное сообщение без подмены.
- Длинные серверные вклады (`68.1818…`) показываются как `≈68,18` с точным значением в
  подсказке; сравнение использует точную строку. На ширине ≤760 px строки становятся
  карточками «Было/Стало».

## 3. Компактная сводка запуска

`RunSummary` (в `RunDetails.tsx`) стоит сразу под итогом карточки: новый вызов или
переиспользование (со ссылкой на исходную оценку), время получения, версия правил, профиль,
модель «запрошена → по ответу API», длительность задания (первая попытка → последняя) и
отдельно сумма длительностей вызовов, число вызовов и попыток, токены вход/выход, стоимость.
Признак тестового оценщика сохранён.

- Стоимость — только серверная `EvaluationRun.cost/cost_complete`: подтверждённый ноль
  («платных вызовов не было»), «неизвестна», «неизвестна полностью; известная часть …».
- Токены суммируются только из `input_tokens`/`output_tokens` вызовов запуска; reasoning и
  cached не добавляются; при неполных данных — «известно для N из M».
- Переиспользование: расходы исходного результата читаются из `run` исходной оценки
  (`GET /evaluations/{id}`) и показываются отдельно, «к текущему запуску не прибавляются».
- Без `run` — «нет истории запуска»; вызовы артефакта не подставляются.
- Раскрываемая часть «Детали запуска…» сохранила прежнее содержимое (тестовые ID тоже) и
  дополнена ID оценки, ключом reuse, хешами входа, заданием/пакетом и версиями промпта/обработки
  текста — последние берутся из описания профиля с тем же id+version; если сервер его не
  описывает, ничего не подставляется.

## Ограничения

- Предупреждение о разных профилях не проверено E2E: в тестовом режиме доступен один профиль.
  Логика покрыта кодом страницы, не тестом.
- Версии промпта/обработки текста не хранятся в `EvaluationView`; показываются из описания
  профиля с тем же id+version (явно подписано). Защищает только hash профиля из `identity`.
- Токены суммируются в UI из `run.calls` (только input/output) — серверной суммы токенов нет.
- Отступ строки продолжения не сохраняется в тексте (это маркер формата); если важен
  ведущий отступ внутри реплики, используйте JSON-импорт.
- Существование внешнего ID до отправки не проверяется; итог (new/revision/unchanged) сообщает
  сервер после импорта, а при изменённом тексте с уже импортированным ID UI предупреждает заранее.
- Длинный текст опций в выпадающих списках сторон сравнения обрезается браузером на узком экране.
- Настоящий AI не запускался; все сценарии — явный тестовый оценщик, не точность модели.
