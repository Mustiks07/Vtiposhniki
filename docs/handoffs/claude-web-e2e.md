## Что поставлено

**Каркас и данные.** React/TypeScript/Vite, разделы «Диалоги / Чек-листы / Апелляции»,
hash-маршруты (сервер раздаёт сборку через StaticFiles без SPA fallback, поэтому refresh
глубокой ссылки работает только так). URL хранит карточку, пакет, критерий, вид на узком
экране, фильтры и страницу. Клиент `src/api/client.ts` поверх generated TypeScript,
`APIError` с `correlation_id`, отмена устаревших чтений, localStorage не используется.

**Импорт, список, пакет.** JSON (файл/вставка, JSONImport v1) и organizer API (только
`group_id`); индексированные ошибки сервера, атомарность. Фильтры язык/канал/статус,
пагинация, мультивыбор, revisions разговора. Запуск: чек-лист, закрепляемая версия,
профиль, fresh/reuse_if_compatible; ключ идемпотентности привязан к payload, синхронная
защита от двойного клика, повтор после ошибки тем же ключом. Экран пакета: счётчики,
состояние каждого задания, попытки/предел, `next_attempt_at`, «обработка завершена,
оценка неполная», ручной retry из `failed`/`retry_wait`, ограниченный polling с нарастающим
интервалом и восстановлением после недоступности сервера.

**Карточка.** Транскрипт и критерии рядом; на узком экране — вкладки и возврат к критерию.
Automatic и effective раздельно, объяснения `incomplete_evaluation` и `no_applicable_weight`
(не 0), секции с подписями (проценты не суммируются), флаг отдельно от итога, ступень `7/10`
отдельно от `10,5/15` и нормализованного вклада, N/A с причиной, undetermined как
ограничение, конфликт reviewer, доказательства message/range/source (подсветка всего
включительного диапазона, фокус на первой реплике, фрагмент источника только из
`source_fragments`, отсутствующий источник обозначен). Детали запуска: версии, фактические
модели, длительность, стоимость всех вызовов (неизвестная не превращается в 0), reuse
provenance. Аудио: `<audio>` по `access_path?revision=<pinned>`, seek только при verified
mapping. Текст реплик — только текстовые узлы, ссылки не создаются.

**Редактор и версии.** Новый чек-лист / новая версия с `expected_latest_version_id`;
binary/scale/flag, вес, секции, варианты (`raw_value`, anchor, явная доля), N/A с условием,
инструкции каналов, политика доказательств, источник, ответы-нарушения. ID существующих
критериев сохраняются, новые — непрозрачные; перестановка, удаление, «заменить новым».
raw/max только для шкалы с нулём внизу; ненулевая или обратная шкала требует явного
подтверждения mapping. Ошибки у полей, черновик сохраняется при отказе. Сравнение версий,
уведомление о смене только весов, запуск с выбранной версией.

**Апелляции и экспорт.** Апелляция из критерия с `expected_revision`; очередь с исходным
ответом AI, комментарием, текущими доказательствами и подсвеченным фрагментом. Решение:
подтвердить/изменить с обязательной причиной; replacement по снимку критерия, с диапазоном
реплик-основанием, `human_changed`. 409 показывается как конфликт с сохранением ввода и
явным «Обновить данные». После решения EvaluationView читается заново; сравнение
«AI → решение → итог». Экспорт — ссылки на серверные JSON/CSV с выбором automatic/effective.

Баллы во frontend не вычисляются. Fixtures используются только в unit-тестах.

## Ограничения

- Все сценарии используют явный тестовый оценщик foundation; real-provider smoke не
  проводился (ключей и production-профиля нет, см. B R-1).
- E14 source и E15 verified seek на реальном API недостижимы: тестовый оценщик не выдаёт
  source evidence, а B не заполняет audio mapping. Оба покрыты component-тестами на
  fixtures. Воспроизведение настоящей записи не проверялось (нет organizer-аудио).
- E01 organizer: без подменного транспорта проверяется только запрос и безопасный отказ.
- E05 `retry_wait`: синтетический сценарий `failed` неретраемый, состояние `retry_wait`
  на реальном API не наблюдалось (UI для него есть: попытки, `next_attempt_at`, retry).
- E20 200% проверен эквивалентным viewport, а не браузерным zoom; скринридеры не проверялись.
- Размер production-бандла ~440 КБ (без code splitting).

   На ветке C без B шаг `npm run e2e` падает по замыслу; проверять на integration-ветке.
2. **Тестовый setup B** (без новых публичных маршрутов): подменный транспорт организаторов,

   E01 organizer, E05 retry_wait, E14 source и E15 seek в браузере не проверить до конца.
3. **SPA fallback** на сервере (необязательно): позволил бы обычные маршруты вместо hash.
4. Порт 8000 на машине разработчика может быть занят: `vite.config.ts` принимает
   `CQA_API_ORIGIN`, E2E — `CQA_E2E_PORT` (только apps/web).

## Запуск

```sh
npm run build
CQA_E2E_API_ROOT=<checkout с apps/api B> npm run e2e
```

По умолчанию API берётся из этого репозитория. Результаты и временные файлы E2E пишутся
в игнорируемый `data/private/`.
