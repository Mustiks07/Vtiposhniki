## C2: редактор чек-листов и версии

- `/checklists/new` и `/checklists/:id/edit?from=<version>`: черновик → новая неизменяемая
  версия (`POST /checklists` или `/checklists/{id}/versions` с `expected_latest_version_id`).
- Поля критерия: название, определение, тип binary/scale/flag, вес, секция, варианты
  (`raw_value`, anchor, явная `score_fraction`), N/A с обязательным условием, инструкции
  для каналов, политика доказательств, необходимость источника, ответы-нарушения для флага.
- Добавление/удаление/перестановка/«заменить новым» (новый непрозрачный ID); ID существующих
  критериев сохраняются. Подсказка raw/max только для целочисленной шкалы с нулём внизу;
  ненулевая нижняя ступень или обратная шкала требуют явного подтверждения mapping.
- Ошибки рядом с полями; при отказе сервера черновик остаётся; 409 объясняется.
- Список версий, сравнение двух версий (определения, варианты, доли, N/A, веса, секции,
  порядок), уведомление о смене только весов (reuse_if_compatible), запуск с версией.

## C1: что сделано

- Каркас React/TypeScript/Vite: навигация «Диалоги / Чек-листы / Апелляции», hash-маршруты
  (обновление страницы восстанавливает карточку, пакет, выбранный критерий и фильтры из URL).
- Типизированный клиент `apps/web/src/api/client.ts` поверх generated TypeScript
  (`contracts/typescript/api.d.ts`), единая обработка `APIError` с `correlation_id`,
  отмена устаревших запросов через `AbortSignal` (react-query).
- Импорт JSON (файл/вставка, формат JSONImport v1) и organizer API (только `group_id`);
  индексированные ошибки сервера показываются как есть, атомарность объяснена.
- Список разговоров: фильтры язык/канал/статус в URL, пагинация, множественный выбор.
- Запуск пакета: чек-лист, закрепляемая версия, профиль, режим fresh/reuse_if_compatible;
  ключ идемпотентности привязан к payload, синхронная защита от двойного клика.
- Экран пакета: счётчики, состояние каждого задания, попытки/предел, `next_attempt_at`,
  «обработка завершена, оценка неполная», ручной retry только для `failed`; ограниченный
  polling с нарастающим интервалом, прекращается в финальном состоянии.
- Карточка оценки: транскрипт и критерии рядом (на узком экране — переключатель с
  возвратом к критерию), automatic и effective раздельно, секции, флаги отдельно от итога,
  ступень шкалы (`7/10`) отдельно от взвешенного результата (`10,5/15`) и нормализованного
  вклада, N/A с причиной, undetermined как ограничение, reviewer-конфликт, доказательства
  message/range/source (подсветка всего включительного диапазона, фрагмент источника
  из `source_fragments`), детали запуска (модели, длительность, стоимость, неизвестная
  стоимость не превращается в 0), происхождение reuse.
- Аудио: настоящий `<audio>` по `access_path?revision=<pinned>`; seek только при
  `alignment_status=verified` и mapping; иначе явное ограничение.
- Формы апелляции и решения (confirmed/changed с replacement по снимку критерия,
  `expected_revision`, обработка 409 без потери ввода) и очередь апелляций —
  написаны, но **на реальном API не проверены**: в B1 эти маршруты отвечают 501.
- Экспорт: ссылки на серверные маршруты JSON/CSV с выбором automatic/effective
  (в B1 отвечают 501).
- Баллы во frontend не рассчитываются: только форматирование строк ScoreSummary.
  Fixtures используются только в unit-тестах; в приложении fixture-режима нет.

## Запуск E2E

`npm run e2e` поднимает три настоящих API в тестовом режиме (сценарии complete/partial/
failed, порты 8765–8767, отдельные БД в `data/private/c-e2e/<run>`), раздаёт production-сборку
web через `CQA_WEB_DIST`. API берётся из `CQA_E2E_API_ROOT` (по умолчанию — этот репозиторий).
На ветке C без кода B global setup завершается явной ошибкой (не skip).
